# Source and tool provenance — DRAFT

The supplied project is [madsim-rs/MadRaft at `8ec4565ecd3844f54f52865f2d7b3da4044f657f`](https://github.com/madsim-rs/MadRaft/tree/8ec4565ecd3844f54f52865f2d7b3da4044f657f), inspected from a public upstream checkout. All four source/lab families and their tests are retained. `madraft/LICENSE` is the original Apache License 2.0, and `madraft/README.md` retains upstream attribution to MIT 6.824 and PingCAP's talent plan. The upstream CI YAML is not installed as this repository's CI. Upstream supplied no lockfile; this experiment commits its resolved `madraft/Cargo.lock`.

The old dependency constraint selected MadSim 0.1.3. An actual Rust 1.92 build failed with E0512 in RPC code: `TypeId` is 128 bits but the old implementation transmutes it to `u64`. The replacement dependency is [MadSim 0.2.34 at `519950efb4711464f300ed7edf2967ed62d5f502`](https://github.com/madsim-rs/madsim/tree/519950efb4711464f300ed7edf2967ed62d5f502), pinned in Cargo.toml. This is a disclosed dependency upgrade, not a silent change to the selected MadRaft revision. The actual failure and adaptation diff are in `runs/preparation/`; they are local diagnostics, not another source archive.

Compatibility changes are limited to the following mechanics. The `todo!` student bodies remain incomplete.

- RPC uses typed `net::rpc::Request` with distinct numeric method IDs, `Endpoint::bind` and the single-type-parameter call API. Raft and its hosted service share the bound endpoint. These IDs select RPC types; they are not new content hashes or proof certificates.
- Test nodes are explicitly created with stable identity, named by their existing addresses; the same node/storage is restarted. Server test ports are 1 because port 0 now requests an ephemeral endpoint. Network partitions and file-size queries use node IDs rather than old address handles. The peer groups and fault operations are unchanged.
- Modern joined tasks return `Result`; the adapted joins unwrap failures instead of silently dropping them. Modern dropped handles detach; the sharded-KV test that used drop to cancel tasks now aborts those tasks explicitly before dropping them. Upstream detached background tasks remain detached.
- Simulator RNG calls use `thread_rng`; import paths for runtime handles, `SliceRandom` and `Duration` follow the new API. No random choices are replaced by wall-clock/system randomness.
- The existing `State`, `Role`, defaults and `is_leader` observer move from `raft.rs` into `raft/state.rs`. Its small Verus postcondition checks the existing observer, and both Cargo and `proof/progress.rs` import this exact source. This is disclosed supplied code, not a generated protocol solution or one of the five safety proofs. The generator can revise that representation.
- Three added `test_support` tests check actual RPC partition/reconnect, task cancellation, and node/file survival through simulator restart. They test host plumbing only. `async-channel = 2.5.0` is pinned for dependency resolution with the selected simulator. The build always uses `--cfg madsim`, so it cannot silently become a Tokio-only run.

There are 57 declared upstream tests: 56 active and one upstream-ignored empty `unreliable3_4b` linearizability placeholder. The separately commented KV linearizability test also remains commented. No new ignore was introduced; neither placeholder counts as passing coverage. The active assertions and test names are retained. Test-plumbing edits, including new join-result handling, are disclosed above. These gaps in upstream application-level coverage must remain visible in the final result.

Preparation uses Verus `0.2026.01.23.1650a05` with its Rust `1.92.0` toolchain and bundled `vstd`/SMT tools, all already installed under the local paths in `tools.ini`. Macro erasure in Cargo and proof checking use that same tool distribution. No global toolchain was replaced. The thin launcher was checked against local Codex CLI `0.162.0-alpha.17.2` help and [official non-interactive execution documentation](https://learn.chatgpt.com/docs/non-interactive-mode): JSON events expose a thread ID, and explicit resume continues that conversation. Model availability is left to the user's configured account, not assumed from a guessed model string.
