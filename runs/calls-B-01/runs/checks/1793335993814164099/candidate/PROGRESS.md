# Progress — round 2

Implemented proposals, exact-byte log replication, conflict repair, log freshness voting, current-term majority commitment, ordered application, full durable log recovery, snapshot creation/compaction, snapshot installation and restart replay. All 23 retained Raft tests now pass on every configured seed 1–5 on the final source. This is functional progress, not proof of the five fixed history properties. Applications remain unfinished.

Actual proposal path: callers enter `RaftHandle::start`, acquire the operation mutex, invoke `Raft::start`, persist the appended command, then replicate. `Raft::start` checks leadership, calls checked `state::next_log_index`, appends the actual command bytes and updates its own match slot. `send_vote_request` now supplies actual last-log term/index; `Raft::request_vote` calls checked `state::log_fresh` before `State::vote`. Constructor membership validation establishes `Ballots::new`'s `me < members`; `Ballots::record` preserves the invariant required by `State::elected`, including after restart because recovery precedes fresh ballot construction. Async caller composition and deployment/group identity remain unproved.

Actual replication inputs originate in registered `AppendEntries` RPC handlers; replies originate in `Endpoint::call_timeout` for one peer/request, retaining the captured term and acknowledged index. `send_heartbeats` serializes at most one outstanding replication per peer, sends the exact suffix or an installed-snapshot request, ignores obsolete-term replies, and updates the corresponding match slot. `Raft::append_entries` checks leader/term, predecessor index/term, entry-term order and bounds, rejects same-term byte disagreement and changes to committed entries, and truncates only a conflicting uncommitted suffix. `RaftHandle::append_entries` persists before reply/application release. These log-selection, byte-content and reply-provenance decisions still reside in unverified Rust and are explicit protocol proof gaps, not host trust assumptions.

Actual commitment/application: `Raft::advance_commit` chooses a candidate from its real match vector and invokes checked `state::commit_from_matches`; this function computes the exact supporting-slot count using verified `replication_support`, then enforces majority, bounds and current-term restriction. The missing premise is the protocol meaning of every match slot, not an assumed majority fact. Followers invoke checked `state::follower_commit`, bounded by the prefix in that request. `Raft::apply` invokes checked `state::next_application` and sends the exact entry at the resulting original index through `apply_ch`. Helpers have no unchecked input preconditions; actual vector/index relations and output release ordering still need caller verification. No execution/history adapter exists yet, so actual state changes and all sends/application/storage outputs have not entered a proved global history.

Snapshots/recovery: `RaftHandle::snapshot` checks `state::can_snapshot` against base/applied/commit/last, retains a boundary sentinel and suffix, and persists. `install_snapshot` interprets a genuine RPC, checks bounds/terms, retains a matching suffix or replaces it, persists the coherent image, then emits `ApplyMsg::Snapshot`. `cond_install_snapshot` checks the exact resident boundary/term/bytes against the queued message. `restore` reads immutable records, deserializes actual bytes, validates vote continuity via `State::restore_successor`, validates term order, cursor bounds and overlap of previously committed suffixes, restores the physical base, and emits snapshot before suffix commands. Ghost history is not fabricated; its missing derivation remains OPEN. The service snapshot decoder/application semantics is still missing.

Persistent images now contain term, vote, exact retained log, snapshot boundary/bytes and commit cursor in one record; records use `state`, `state.1`, ... and reject an incomplete terminal record rather than forgetting an unknown vote. Known storage limitation: historical images are never reclaimed, so storage is unbounded. The retained size test reads only `state`, the first immutable record, so its PASS does not establish the required current-image or total-storage bound. The separate `snapshot` file is not used; coherent-image persistence is authoritative. Address this representation/accounting gap before claiming completed 2D. The simulator still has synchronous retained-memory writes, no-op `sync_all` and unimplemented power failure; no real-disk durability claim is made.
