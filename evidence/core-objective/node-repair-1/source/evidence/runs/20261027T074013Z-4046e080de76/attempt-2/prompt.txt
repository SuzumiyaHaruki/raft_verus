# Node state and initialization

Status: DRAFT. Module: INCOMPLETE; initial-state types and independent checks exist; constructor generation is pending.

## Responsibility and connections

Represent a fixed-membership Raft node throughout its lifetime: follower,
candidate and leader roles; durable term, vote and log; volatile commit/delivery
positions; election votes, peer replication progress and pending operations.
This state is shared by [elections](elections.md), [replication](replication.md)
and [commitment](commitment.md). The [runtime](runtime.md) serializes events;
[recovery](recovery.md) reconstructs state after a crash.

The shared types are in `crates/raft-verified/src/state.rs`, re-exported by the
library. `Node` currently represents identity, membership, hard state, role,
commit/delivery/application positions, incarnation, serial and deadline. Pending
I/O, peer progress and recovery will extend this same type. They are not represented
by fictitious constant fields in a claimed complete refinement. The model's
`fresh_node`, `initial`, `init` and `well_formed` remain unchanged.

## Module completion

Fresh construction, role-specific fields and recovered construction have explicit
bounds and representations. Every handler uses this state; no parallel test-only
node exists. Tests cover legal/invalid membership, initial state and index/resource
boundaries. Actual proofs establish initialization and representation and supply
the invariant required by handlers. PO-INIT, PO-REPRESENTATION, PO-REFINE-INIT and
index/token lemmas in [proofs.md](proofs.md) remain open until checked.

Execute only the selected step below within its editable scope. The module responsibilities describe the destination, not extra work for this call. Passing this step does not complete the module or the Raft project.

`InvalidMembership`. Initialize term/positions/incarnation/serial to zero, no vote,

`init_result`. It demands success for every valid input, so rejecting all inputs
cannot prove the target vacuously. `crates/raft-proofs/node_init.rs` calls the exact
constructor source compiled by Cargo; weakening its annotation or strengthening
its precondition cannot satisfy the independent caller. This checks only the
represented initial fields, not whole-node/cluster refinement or runtime behavior.
