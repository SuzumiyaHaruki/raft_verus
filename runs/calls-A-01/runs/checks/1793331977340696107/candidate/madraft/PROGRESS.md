# Progress — round 1

Implemented randomized Raft election, candidate-specific votes, heartbeat RPCs, log freshness checks, suffix conflict repair, current-term majority commitment, ordered command delivery, compaction, snapshot transfer and restart. Async mutation/persistence is serialized by RaftHandle::gate. Durable state uses two generation-matched pairs (state/snapshot and state.backup/snapshot.backup), replacing the older pair first and accepting only complete pairs on recovery; unknown durable state fails closed. Added shared replicated service, serialized clerk retries with stable request identity, bounded per-client response deduplication, KV operations, service snapshots and deterministic controller rebalancing. Sharded KV remains the original unfinished scaffold.

Actual checks: build PASS before final cache adjustment; all 24 Raft tests PASS on seed 1 and seed 2 before split-pair storage and on seed 3 after split-pair storage. Foundation PASS. Verus progress PASS (7 verified, 0 errors), importing actual state.rs and checking local term/vote contracts plus two distinct same-term vote calls. KV seed 1 first had 12/19 pass with seven log-size failures; after separating snapshot bytes, 18/19 passed with snapshot_size_3b still failing due unbounded dedup history. Replaced that cache with latest response per serialized clerk; rerun pending. Controller seed 1 first timed out; rerun pending. No five-target, execution correspondence or snapshot fidelity theorem is claimed.

Failed approaches: embedding snapshot bytes in state violated retained log-size bounds; retaining every request response violated the 500-byte snapshot test. Storage now separates the compacted suffix and snapshot, and retry records retain one sequence/result per client. The two-pair crash argument is currently design reasoning, not a machine proof. Local verified voting does not prove durable votes, quorum provenance, or global election safety.
