# Execution correspondence and coverage review — DRAFT

The independent caller in `final.rs` requires five safety theorems, executable refinement, observation shape, snapshot fidelity and a nonempty observable execution witness. These are obligations for the generated implementation, not assumptions supplied by the experiment. `targets.rs` fixes the meanings of the five properties; the generator supplies the execution representation and proofs.

`prove_observation_and_snapshots(run)` must establish `refines_executable(run)`, `targets::shape(observe(run))` and `targets::snapshot_fidelity(observe(run), applications())` for every admitted execution. Splitting the independent execution and snapshot callers only gives separate diagnostics; the complete caller still requires their conjunction. `execution_witness()` must return an `Execution` satisfying `execution`, observation shape, and at least one non-Silent observed event. This additional witness rejects some empty/false execution definitions; it is not a substitute for all-execution coverage or a new liveness claim.

For partial feedback, `python3 scripts/check.py top NAME` uses `madraft/proof/NAME.rs` if provided, otherwise `implementation.rs`, as the implementation module for that one independent caller. Export the interfaces it consumes and import your actual implementation dependencies. The entire imported unit is verified with `--no-cheating`, with no function filter. Separate unfinished units if needed. Full `safety` and `final` always use `implementation.rs` and all callers together; passing independent units is not proof composition by itself.

Keep a concise coverage/dependency account in `PROGRESS.md` and the final `RESULT.md`: actual constructors and handler functions; initialization and admitted-step induction; observable elections, commit advances and applications; every crash/restart and snapshot path; decoder/prefix fidelity; real caller preconditions; exact host primitives and their assumptions. A generic initialization/single-step/history decomposition is useful only when the real generated callers discharge its premises. No particular Raft invariant, backup scheme or ghost representation is prescribed.

Semantic review must examine whether all allowed runtime behavior is represented, events are not filtered, crashes preserve prior history, compacted prefixes are justified, and protocol coordination has not moved into a trusted wrapper. Known bad examples include `execution = false`, permitting only zero steps, an observer emitting only Silent events, or `refines_executable = true`. The witness and limited source checks detect some such constructions. Verus checks the definitions it is given; neither a keyword scan nor a finite set of negative examples decides arbitrary semantic equivalence. A machine-pass report must disclose this boundary and must never be called a proof of full Raft correctness or conditional liveness.
