The core's local contracts establish finite index/membership bounds, checked term increase, candidate freshness, same-term vote preservation and exact transition equations. The proof execution admits finite per-node actions, derives local bounds by induction and observes leader transitions. It has no verified network-authenticity or disk-phase relation; its crash/restart abstraction admits arbitrary well-formed restored election images. Group identity is only present in the developing proof interface, not yet a deployment-refined runtime identity. The tally-to-set-cardinality invariant and global quorum argument remain open. No commit or application path is implemented, and empty-log observations describe only this incomplete election increment.

Storage and snapshots: persistent term/vote images use `bincode`, `fs::File::create("state")`, `write_all_at` and `sync_all`; restore uses `fs::read("state")`. A truncated or undecodable existing image halts construction; it never becomes a fresh vote. This sacrifices availability on incomplete writes. There is no proved write-phase or recovery correspondence yet, no persistent log/snapshot image protocol, and no snapshot boundary, decoder, installed-state or retained-prefix theorem. Snapshot APIs remain placeholders. No real-disk, torn-write or power-loss durability claim is made: the pinned MadSim filesystem makes completed writes durable immediately and `sync_all` is a no-op.

Host/TCB account: the runtime uses `net::Endpoint::{bind,add_rpc_handler,call_timeout}`, `task::spawn`, `time::{Instant::now,sleep}`, MadSim randomness, `std::sync::Mutex`, `futures::lock::Mutex`, futures mpsc construction, serde/bincode and the filesystem functions above. Memory safety, value-preserving serialization, non-forged peer networking, scheduling, mutex mechanics and allocation/failure mechanics have the supplied environment contracts. Their exact asynchronous coordination, handler preconditions and crash cancellation are not yet verified, and no consensus wrapper has been declared trusted to close those gaps. Unknown durable images fail construction, term exhaustion stops campaigns, and invalid membership fails construction before Raft emits protocol output.
