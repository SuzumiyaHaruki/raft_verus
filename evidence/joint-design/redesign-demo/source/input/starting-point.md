# Experiment inputs and generated design

Status: DRAFT. Start without working Raft protocol behavior. The experiment generates one Rust implementation and its implementation-layer Verus specifications and proofs together. Supplied interfaces and independent requirements remain explicit inputs; this is not unconstrained synthesis from blank files.

## Supplied requirements and checks

`raft-spec` contains candidate behavioral targets and the Raft model. `raft-proofs` contains protected callers connecting actual executable methods to those targets. Message types, observable-state vocabulary, API signatures, independent tests, host replay/measurement drivers and tool configuration are supplied. These inputs require review for adequacy; Verus does not prove that a chosen specification is the intended Raft. No target or assumption is approved by a passing local experiment.

## Generated implementation and specifications

For STATE-INIT and RUNTIME-PERSIST, `src/node_state.rs` is an editable starting layout, not a required internal representation. Generate or revise Node's fields, helpers, `view`, representation invariant `wf`, and executable inspection/construction adapters. `src/contracts.rs` contains deliberately vacuous implementation-contract seeds: replace or reorganize them alongside `node.rs` and `persistence.rs`. Choose algorithms, function decomposition, local postconditions, auxiliary invariants and proofs within the task's scope. Other modules allow their corresponding executable and lemma files. Do not prefill a protocol solution from maintenance examples.

`Observation` in `src/state.rs` describes what independent callers inspect; it is not the required internal Node layout. `observe()` must expose the actual executable observation corresponding to `view()`. `from_observation()` is a boundary-test adapter, not crash recovery or a legal Raft transition. It must represent every supplied observation faithfully and establish `wf`; this preserves boundary tests such as counter exhaustion and prevents an impossible invariant from making the checks vacuous. The initial adapters only wrap/read the supplied record and implement no Raft operation. `wf` therefore concerns representation consistency; reachable-state protocol invariants require separate initialization/preservation proofs. The borrowed `Observation` adapter is a supplied interface constraint, not freedom to change every public API. Public fields in the starting layout permit this Verus release's open specifications; consumers use the observation API, not those field names.

## Independent correspondence

A constructor must accept every valid membership, establish `wf` and the independent initial-state target. Each checked handler must preserve `wf` and satisfy its independent relation over observations and actual returned results. The protected observation consumer checks the executable observer against the generated view. Changing the local contract to true, excluding all states with false invariants, or describing an unrelated ghost state cannot replace these obligations. Implementation contracts may be weaker or stronger internally only when the independent callers still verify without stronger environmental premises.

The controller reuses one candidate, history and cumulative budgets across generation, repair, local redesign and continuation. Previously completed tasks are rechecked; future unfinished tasks are not current prerequisites. Report ordinary implementation-specification changes in changed_files and summary. Reserve proposed_spec_changes for protected behavioral requirements or assumptions; such a proposal is delivered for review rather than silently adopted. Human review occurs after delivery, not through an approval file inside the loop.

Offline scripts/solutions and historical evidence are excluded from candidate copies. SIMULATED generation remains distinct from real Rust/Verus checking. New runs copy the checked-out scaffold; resume retains that run's generated code and design. Do not retrieve external answers. Directory exclusion is not hostile-process OS isolation. Full Raft safety, conditional liveness and cluster refinement remain open.
