# Progress — round 3

Reconsidered the earlier decomposition: verified election/cursor helpers do not prove actual async constructors, log mutations, recovery or output histories. These are missing caller/refinement proofs, not solver failures or a demonstrated unsafe initialized trace. No invariant was asserted to exclude allowed behavior. Preserved the passing Raft implementation while adding its missing service/decoder dependencies and repairing the storage representation/accounting defect.

Changed storage: `RaftHandle::persist` writes an immutable coherent `image.N` containing term/vote/log/base/commit/snapshot, awaits its completion, updates `state` (current metadata excluding snapshot bytes) and `snapshot` (actual current snapshot bytes) mirrors, then clears the preceding image using the pinned simulator's `File::open`/`set_len`. `restore` scans numbered records, skips reclaimed empty records only when a later complete record exists, rejects an empty/incomplete terminal record, validates/decode-restores the authoritative image, and ignores potentially interrupted mirrors. No multi-file atomicity is assumed. Old metadata filenames still accumulate; repeated crashes before reclamation can retain older complete images, so a full storage bound and recovery-time garbage collection remain OPEN. The new test `snapshot_image_survives_interrupted_mirrors` creates a real committed snapshot, checks obsolete-image reclamation, truncates both mirrors, kills/restarts the node, and checks the restored snapshot output.

Changed executable service path: `ClerkCore::call` serializes calls per client, obtains a checked sequence, retains the exact client/sequence/command across network retries, and tracks a responding leader. `Server::apply` serializes that identified request to actual Raft bytes, starts agreement, then polls committed results with term/timeout checks. The apply worker from `Server::new` receives actual `ApplyMsg` commands, checks contiguous original indices, invokes `sequence::new_request`, applies only a newer client sequence, and caches the result. It serializes `Machine<S>` (state, applied boundary, latest result per client) into snapshots; received snapshot bytes are decoded and boundary-checked before replacement. Both writes and reads enter the Raft log. These real service decoders/outputs exist now, but their semantic fold and connection to the Raft history remain unproved. Random client IDs also require an identity-collision treatment before any application-correctness claim.

Implemented KV get/put/append and shard-controller historical query/join/leave/move with deterministic balancing and minimal preservation of existing ownership. Raft RPC IDs now occupy a separate range from service RPC IDs. `ClientRequest<T>` carries retry identity on the wire, and `Replicated` carries it in exact consensus bytes. Fixed an actual simulator environment defect: retained controller clients run on the unaddressed main node, and the pinned network drops remote sends from a node without an IP. Client construction assigns node 0 a stable documentation-range source IP; other client/peer topology is unchanged. The first repair tried name lookup, but main is not in the runtime's named-node map and that lookup panicked; using `plugin::node()` fixed the adapter without changing original tests.

Preconditions/callers: `try_new` establishes fixed nonempty membership and member bounds before core calls; recovery runs before RPC/ticker startup. The shared ballot invariants still originate in `Ballots::new` and are preserved by `record`. New `sequence::{next_sequence,new_request,snapshot_boundary}` are total checked functions used directly by the real client/service worker and imported into `proof/progress.rs`; no recovery-only unchecked precondition was added. The constructor, message interpretation, dedup state continuity, real bytes decoding, match-slot provenance and persistence-before-release compositions remain unverified. There is still no `proof/implementation.rs` execution adapter, so the new and old mutations, obsolete replies, storage completions and service outputs do not yet enter a proved global history. All five fixed theorem outcomes stay OPEN.
